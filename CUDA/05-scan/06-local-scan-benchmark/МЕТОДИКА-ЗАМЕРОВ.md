# Как получена таблица сравнения Scan

Таблица в конспекте и слайдах показана на занятии 12 октября 2026 года. Она сравнивает три реализации локального exclusive Scan на одинаковом входе и не измеряет завершённый Scan всего массива.

## Вход и реализации

Вход содержит 4194304 значения int. В позиции `i` записано `(i * 17 + i / 29) % 23 - 11`, где деление целочисленное. Для каждого блока CPU-эталон начинает сумму с нуля и сравнивает каждую выходную позицию. Такая проверка соответствует локальным exclusive-префиксам.

Hillis–Steele использует ядро из авторского `01.5-correct_cuda_scan.cu`. Изменена только финальная запись: inclusive-префиксы сдвинуты на одну позицию, а первый результат блока равен нулю. Внутренние операции и барьеры сохранены.

Blelloch использует точное тело ядра из авторского `02-two-layer-parallelism.cu`, включая барьер каждого уровня down-sweep. Padding не добавлен. Файл `correct_scan.cu` без этих барьеров в сравнении не участвует.

Третий вариант использует отдельное дополнение `warp_scan.cuh`: shuffle внутри полных warp, суммы warp и два барьера shared memory между warp. Все три варианта возвращают одинаковый вид результата.

## Устройство и границы таймера

Измерение выполнено на RTX 2080 Ti. Сборка: CUDA toolkit 13.4.92, `nvcc -O3 -std=c++17 -arch=sm_75`. Проверены блоки 32, 64, 128, 256, 512 и 1024 потока.

CUDA events стоят в одном nonblocking stream до и после пачки из 25 запусков. Событие остановки ожидается перед чтением времени. Мы выполняем десять прогревочных пачек, затем пять измеряемых. Время каждой пачки делим на 25 и берём медиану пяти результатов. Таблица показывает миллисекунды на запуск всей сетки блоков.

Выделение памяти, H2D, D2H и CPU-проверка находятся вне таймера. В таймер также не входят Scan сумм блоков и добавление глобальных смещений. Поэтому эти числа нельзя сравнивать напрямую со временем готового глобального Scan вместе с копированиями.

## Повторение на своём GPU

В этом тематическом стенде сохранены точные измеренные исходники. Из его каталога собираем и запускаем пример:

```bash
nvcc -O3 -std=c++17 -lineinfo -arch=sm_75 main.cu -o main
./main --size 4194304 --warmup 10 --repetitions 5 --batch 25
```

Для другой модели GPU выбираем соответствующую архитектуру. Авторские варианты требуют длину, кратную 1024; это ограничение их обработки хвоста, а не математическое условие Scan. Числа времени выводятся только после проверки результатов каждой измеряемой пачки. Из этих чисел сами считаем медианы.

Выгрузка примера не обещает тот же порядок времён на другом GPU. Частоты, нагрузка, компилятор, число блоков и тип данных могут изменить результат. Результат измерения говорит, какой вариант оказался быстрее в этих условиях. Причину разницы устанавливаем отдельным профилированием.
