# CUDA. Лекция 4: примеры и пояснения

Код к лекции 4 по CUDA от 12 октября 2026 года. Авторские исходники находятся в [CUDA/05-scan](../05-scan) и [CUDA/08-streams-events](../08-streams-events). В этом каталоге собраны дополнения в `demo`, отдельные исправления в `corrections` и воспроизводимое сравнение в `benchmarks`. Имена, комментарии и последовательность авторских файлов сохранены.

## Авторский Scan

Мы начинаем с `00-naive_scan.cu`, где последовательный CPU-цикл строит inclusive-префиксы. В исходнике вокруг CPU-работы записываются CUDA events. Для измерения CPU используем отдельную копию `corrections/00-naive_scan_cpu.cpp`: тот же цикл и массивы, таймер `std::chrono::steady_clock`, проверка каждого префикса после остановки таймера.

Из корня этого каталога собираем CPU-копию обычным компилятором C++:

```bash
g++ -O2 -std=c++17 corrections/00-naive_scan_cpu.cpp -o scan_cpu
./scan_cpu
```

Для массива из 1048576 единиц последний inclusive-префикс равен 1048576. Программа проверяет все позиции и завершится с ненулевым кодом, если обнаружит неправильное значение. Выделение памяти, заполнение входа и проверка результата не входят в напечатанное время цикла.

В `01-naive_cuda_scan.cu` мы намеренно видим гонку: один уровень одновременно читает и перезаписывает shared-массив. В `01.5-correct_cuda_scan.cu` новый уровень сначала вычисляется во второй половине shared memory, затем после барьера копируется в первую; следующий барьер отделяет новый раунд. Результат inclusive и локальный для каждого блока.

В `02-two-layer-parallelism.cu` up-sweep, обнуление корня и down-sweep строят локальный exclusive Scan. Между уровнями стоят барьеры. Для заданных размеров программа не содержит обработки неполного блока. Комментарии с inclusive-результатами в некоторых местах не соответствуют коду после обнуления корня; ориентируемся на фактически выполняемые операции.

Несколько сохранённых файлов требуют отдельного внимания:

- `correct_scan.cu` не содержит барьера между уровнями down-sweep. Для многоварпового блока результат может зависеть от гонки. В качестве полного варианта дерева рассматриваем `02-two-layer-parallelism.cu`.
- `01.75-recursive_cuda_scan.cu` не компилируется, пока закомментировано объявление `step_cnt`. Кроме этого, финальная запись всегда читает первую половину shared memory. При нечётном числе раундов результат лежит во второй половине. Программа задаёт два уровня обработки для конкретного размера массива, а не общую рекурсию для любых размеров.
- `03-scan-bank-conflicts.cu` добавляет padding shared memory. Размер выделенного shared-массива должен включать этот padding. Такое изменение уменьшает определённые конфликты банков, но само по себе не обещает выигрыша времени на любом GPU.
- Авторский README описывает 01.5 как обработку всего массива. По коду это локальные префиксы отдельных блоков; для глобальных префиксов нужен следующий уровень сумм и добавление смещений.

## Проверенные дополнения

В `demo/compaction_scan.cu` мы доводим идею сумм блоков до глобального exclusive Scan: нейтральный хвост, рекурсивные уровни и добавление смещений. Затем фильтруем значения строго больше трёх. CPU-эталон сверяет каждый префикс, количество, значения и порядок оставшихся элементов.

В `warp_scan.cu` и `warp_scan.cuh` мы строим локальные exclusive-префиксы через shuffle полных warp. Первый warp считает префиксы сумм warp; два барьера защищают обмен через shared memory. Этот пример не добавляет смещения между блоками.

В `overlap_orders.cu` мы сохраняем точный авторский `busy_kernel` и сравниваем baseline, interleaved и batched. Host-память закреплена, данные участков независимы, завершение всех worker streams явно связано с событием остановки. Время охватывает H2D, вычисления и D2H; проверка результата выполняется после замера.

Команды и параметры находятся в [README дополнений](demo/README.md). Для другой модели GPU выбираем подходящее значение `-arch`. Возможность перекрытия копирований и ядер зависит от устройства и ресурсов, поэтому сначала проверяем правильность результата, затем измеряем время.

## Авторские Streams и Events

В `00-events-timing/main.cu` сравниваем host-таймер без ожидания, host-таймер с ожиданием завершения GPU и CUDA events. У таймера без ожидания другое содержание измерения: возврат вызова запуска не означает завершения ядра.

В `01-async-memcpy/main.cu` сравниваем обычную host-память, pinned-память и `cudaMemcpyAsync`. Программа после постановки копирования ожидает событие; это измерение завершённой передачи, а не только времени возврата API. Числа bandwidth делятся на 1024 в третьей степени, поэтому подписанные `GB/s` фактически являются GiB/s.

В `02-overlap-compute-copy/main.cu` worker streams создаются через `cudaStreamCreate`, а события таймера записываются в legacy stream 0. Такой вариант использует неявные зависимости default stream. Если мы меняем streams на nonblocking или включаем per-thread default stream, нужно явно дождаться всех работ перед событием остановки. Проверенное дополнение демонстрирует именно этот join.

## Исправление барьера в correct_scan.cu

В `corrections/correct_scan_barrier.cu` добавлен один безусловный `__syncthreads()` внутри каждого уровня down-sweep. Файл `.patch` показывает точную разницу с оригиналом. Барьер выполняют все потоки блока, включая неактивные на данном уровне. Барьер после всего цикла приходит слишком поздно: следующий уровень уже мог прочитать незавершённые записи предыдущего.

Это минимальное пояснённое исправление. Оно не добавляет обработку хвоста или межблочные смещения и не проходило новый GPU-прогон: на компьютере сборки нет NVIDIA GPU. Для запуска уже проверенного дерева используем авторский `02-two-layer-parallelism.cu`, где барьер между уровнями присутствует. Показанная таблица сравнения измеряла именно его, а не `correct_scan.cu`.


## Сравнение реализаций

[Методика замеров](МЕТОДИКА-ЗАМЕРОВ.md) описывает вход, границы таймера и повторения. Сравнение локальных префиксов нельзя выдавать за время готового глобального Scan. Для сборки примеров используется установленный CUDA toolkit; CMake этого репозитория их автоматически не подключает.
