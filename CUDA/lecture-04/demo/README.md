# Демонстрации лекции 4: Scan, Compaction и Streams

Мы продолжаем авторские примеры из `CUDA/05-scan` и `CUDA/08-streams-events`. Оригиналы находятся в [05-scan](../../05-scan) и [08-streams-events](../../08-streams-events). Дополнения ниже доводят локальный Scan до обработки полного массива и позволяют проверить порядок выдачи операций без зависимости от stream 0.

## Сборка

Из каталога `CUDA/lecture-04/demo` собираем обе программы. Для учебной RTX 2080 Ti выбираем sm_75. Команды требуют установленного CUDA toolkit; для другого GPU выбираем его архитектуру:

```bash
nvcc -std=c++17 -O3 -lineinfo -arch=sm_75 compaction_scan.cu -o compaction_scan
nvcc -std=c++17 -O3 -lineinfo -arch=sm_75 overlap_orders.cu -o overlap_orders
```

Для другой модели GPU выбираем подходящую архитектуру вместо `sm_75`. Заголовок `busy_kernel.cuh` содержит точную копию ядра из авторского `02-overlap-compute-copy/main.cu`, без изменения операций ядра.

## Scan и стабильная фильтрация

В `compaction_scan.cu` мы оставляем элементы входного массива, строго большие трёх. Маска содержит единицу для выбранного значения, а exclusive prefix задаёт его позицию в выходе. Благодаря префиксам порядок оставшихся элементов совпадает с исходным.

Один блок из 256 потоков обрабатывает 512 значений через up-sweep и down-sweep. Вместо отсутствующих элементов последнего блока мы загружаем нули. Все исполнители доходят до каждого `__syncthreads()`, поэтому обработка хвоста не нарушает барьеры.

Для полного массива программа вычисляет суммы блоков, рекурсивно строит их exclusive prefixes и добавляет смещения к локальным результатам. После scatter последний входной индекс записывает количество выбранных элементов. Случай пустого массива проходит отдельно без запуска ядра.

Начинаем с короткого примера, затем проверяем границу блока:

```bash
./compaction_scan --size 8 --pattern sample --warmup 3 --repetitions 3
./compaction_scan --size 513 --pattern mixed --warmup 3 --repetitions 3
./compaction_scan --size 1048579 --pattern mixed --warmup 3 --repetitions 3
```

Параметр `--pattern` принимает `sample`, `mixed`, `all` и `none`. CPU-проверка сравнивает количество, значения и порядок выхода после каждого запуска, затем проверяет каждый глобальный префикс. Размер ограничен диапазоном от 0 до 67108864, поэтому сумма бинарной маски помещается в `int`.

CUDA events измеряют копирование входа, вычисления и D2H. Для простоты мы возвращаем выходной буфер полной входной ёмкости, затем используем только первые `count` значений. Отдельное копирование префиксов для проверки находится вне таймера. Выделение памяти и построение CPU-эталона также исключены.

## Порядок копирований и ядер

В `overlap_orders.cu` мы сохраняем авторский `busy_kernel`, который многократно применяет арифметическую операцию к каждому элементу. Задача отличается от Compaction и позволяет отдельно наблюдать копирования и вычисления.

Мы сравниваем три порядка работы:

- `baseline` обрабатывает весь массив в одном stream.
- `interleaved` выдаёт для каждого из четырёх участков сначала H2D, затем ядро и D2H.
- `batched` выдаёт H2D для всех участков, после них все ядра, а затем все D2H.

В пределах одного stream операции упорядочены, а каждый участок занимает непересекающийся диапазон памяти. Благодаря независимости данных мы можем запускать разные группы операций одновременно. Host-буферы выделены через `cudaMallocHost` и остаются действительными до завершения работы.

```bash
./overlap_orders --size 4194307 --iterations 80 --warmup 5 --repetitions 3
./overlap_orders --size 16777219 --iterations 80 --order interleaved --warmup 5 --repetitions 3
```

Все streams созданы с `cudaStreamNonBlocking`. Отдельный coordinator записывает старт, каждый worker ожидает его через `cudaStreamWaitEvent`. После своей D2H-копии worker записывает `done`, а coordinator ожидает все `done` перед записью остановки. CPU читает результат только после `cudaEventSynchronize(stop)`. Такой порядок не полагается на неявную синхронизацию stream 0. Правила ожидания и повторной записи событий описаны в [Stream Management](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__STREAM.html) и [Event Management](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__EVENT.html).

Таймер охватывает полный путь H2D, вычисления и D2H, включая ожидание завершения всех участков. Отдельно программа выводит время CPU от постановки старта до возврата после остановки. Проверку значений мы выполняем после таймера с относительным допуском 0,00001 по CPU-эталону с `std::fma`.

Оба порядка с четырьмя streams могут давать разное время на разных GPU. Возможность перекрытия зависит от оборудования и доступных ресурсов, поэтому программу используем для измерения, без заранее обещанного победителя. Перед замером выполняем прогрев, затем собираем минимум три повторения и считаем медиану.

## Scan через warp

В warp_scan.cuh каждый полный warp считает inclusive префиксы через __shfl_up_sync. Первый warp выполняет Scan сумм warp, затем два барьера shared memory сохраняют нужный порядок. Ядро выдаёт локальные exclusive префиксы каждого блока. Суммирование между блоками показано отдельно в compaction_scan.cu.

Размер блока кратен 32 и не превышает 1024 потока. Один поток обрабатывает один элемент, хвост заменяется нулями; каждый поток продолжает участвовать в shuffle и барьерах. Для целочисленной суммы без переполнения exclusive получается вычитанием исходного значения из inclusive. Для других операций вычитание может быть недоступно.

```bash
nvcc -O3 -std=c++17 -lineinfo -arch=sm_75 warp_scan.cu -o warp_scan
./warp_scan --size 1024 --block 1024
./warp_scan --size 513 --block 1024
./warp_scan --size 0 --block 1024
./warp_scan --size 4097 --block 256 --pattern signed
```

Основной запуск использует массив единиц. В warp 7 у lane 17 префикс равен 241; CPU проверяет каждую выходную позицию. Пустой вход пропускает запуск ядра. Параметр pattern signed задаёт вход с положительными и отрицательными значениями. Пример проверяет корректность и не печатает замер производительности.

## Стык с авторскими примерами

В `01-naive_cuda_scan.cu` обновление общего массива внутри раунда создаёт гонку чтения и записи. В `01.5-correct_cuda_scan.cu` дополнительный буфер и два барьера разделяют вычисление новых значений и их перенос на следующий раунд. Оба варианта строят префиксы внутри отдельных блоков.

В `02-two-layer-parallelism.cu` мы видим локальный exclusive Scan Blelloch. Для полного массива к его результату нужны суммы предыдущих блоков. Файл `01.75-recursive_cuda_scan.cu` намечает добавление таких смещений, но в текущем источнике объявление `step_cnt` закомментировано, поэтому версия требует исправления перед сборкой. Дополнение сохраняет авторскую идею и отдельно реализует полный массив с обработкой хвоста.

В авторском `02-overlap-compute-copy/main.cu` события записаны в legacy stream 0, а worker streams созданы через `cudaStreamCreate`. По этой причине между очередями возникают неявные зависимости. Дополнение показывает явный join для nonblocking streams, добавляет проверку результата и повторные замеры. Подпись `GB/s` в оригинале соответствует делению на 1073741824, то есть GiB/s.
